# Dormeza — сайт

Український аналог моделі повного циклу супроводу сну (як у Sleep Reset), побудований
за нашою методологією: ТЗ `Технічне завдання на створення сайту Dormeza Сон 6` та
`Dormeza Сон 6 — Основний документ продукту`.

Ключова відмінність від первинної версії ТЗ: сайт закриває **повний цикл**, а не лише безсоння.
Скринінг розводить людину на два маршрути — поведінкова програма Сон 6 або маршрут порушень
дихання уві сні з обстеженням, лікарем і підбором капи MAD чи СІПАП-апарата.

## Швидкий старт

```bash
cd site
python3 -m http.server 8000
# http://127.0.0.1:8000
```

Збірки немає: це статичні файли. Внутрішні сторінки (доказова база + юридичні документи)
генеруються з одного шаблону, щоб header і footer не розсинхронізувались:

```bash
python3 tools/build_pages.py
```

Правити ці сторінки треба **у `tools/build_pages.py`**, а не в згенерованих `.html`.
`index.html` і `apnea.html` редагуються напряму — вони унікальні за версткою.

```

├── privacy.html               політика конфіденційності          (чернетка)
├── health-data-consent.html   згода на обробку даних про здоров'я (чернетка)
├── terms.html                 умови використання                  (чернетка)
├── offer.html                 публічна оферта                     (чернетка)
├── payment-refund.html        оплата, відмова, повернення         (чернетка)

├── cookies.html               політика cookies                    (чернетка)
├── data-request.html          запит щодо даних                    (чернетка)
├── contacts.html              реквізити й підтримка               (чернетка)
├── robots.txt, sitemap.xml
├── tools/build_pages.py       генератор внутрішніх сторінок
└── assets/
    ├── css/styles.css         дизайн-система: токени + компоненти
    ├── js/config.js           ЄДИНА точка конфігурації (бот, ціни, контакти, версії)
```

## Що правити при змінах бізнес-даних

Усе в `assets/js/config.js`:

| Поле | Що це |
|---|---|
| `botUsername` | username Telegram-бота в усіх CTA |
| `price.regular` / `price.current` | 5 900 / 4 900 грн — підставляються в розмітку через `data-price` |
| `attribution` | довжина й TTL непрозорого токена кампанії |
| `legal.version` / `legal.updated` | версія юридичних документів у футері |
| `contacts` | адреси підтримки |

CTA у HTML мають статичний `href="https://t.me/..."` як fallback без JS; скрипт додає
до нього `?start=<токен>`. Токен непрозорий і не містить персональних даних.

## Правила, вбудовані в код

- **Жодних даних про здоров'я на сайті.** Тут немає форм із питаннями про сон чи симптоми.
- **Аналітика лише після згоди.** До вибору користувача трекери не вантажаться; `dataLayer`
  наповнюється, але нічого не відправляється. Кнопки «Прийняти» й «Відхилити» рівнозначні.
- **У подіях немає медичних полів** — лише `landing_view`, `telegram_click` з позицією CTA,
  перегляди секцій, `faq_open`, `legal_link_click`.
- **Ціна в одному місці.** Розбіжність 5 900 / 4 900 між секціями неможлива.
- **Сторінка читається без JS.** `js-reveal` вмикається лише коли скрипт стартував,
  плюс страховка на 3 секунди.
- **`prefers-reduced-motion`** повністю вимикає анімацію.

## QA, який уже пройдено

- биті локальні посилання — немає;
- по одному `<h1>` на сторінку, ієрархія заголовків без пропусків;
- `lang="uk"` на всіх сторінках;
- контраст усіх пар токенів перевірено розрахунком, `--muted` затемнено до `#4E6B87`
  заради 4.5:1 на світлих фонах;
- console errors у Chromium — немає;
- перевірено 390 і 1440 px, мобільне меню, липкий CTA, cookie-банер, підстановку токена.

Ще не робилося: Lighthouse на продакшн-домені, тестування в Safari/Firefox/Edge,
перевірка на 360/768/1024 px, польові Core Web Vitals.

## Обов'язкові дані до релізу

Позначені в коді як `TODO(release)` / `TODO(legal)` і в тексті як <span class="placeholder">.

1. Реквізити продавця: найменування, ЄДРПОУ/РНОКПП, адреса, телефон.
2. Домен і username Telegram-бота.
3. Платіжний провайдер і узгоджений із юристом порядок повернення для цифрової послуги
   з негайним початком надання.
4. Реальна hero-фотографія (AVIF/WebP + `srcset`) і справжні скриншоти ранкового чек-іну.
5. OG-зображення 1200×630.
6. Конкретні партнери маршруту апное: лабораторія, лікарі, стоматологія, постачальник
   обладнання — з цінами й формою згоди на передачу даних.
7. Строки зберігання даних, перелік процесорів, місця обробки.
8. Ліцензійний статус скринінгових шкал (ISI, STOP-BANG, Epworth, PHQ).
9. Рев'ю українського юриста та клінічного експерта CBT-I / медицини сну.

## Ризики, які треба вирішити поза версткою

- **Статус маршруту апное.** Підбір і постачання СІПАП-апаратів та внутрішньоротових
  пристроїв — це обіг медичних виробів, а діагностика й призначення — медична практика.
  Сайт побудовано так, що Dormeza виступає організатором і супроводом, а всі медичні
  рішення й обіг обладнання лишаються за ліцензованими партнерами. Юридичну конструкцію
  партнерства й модель винагороди треба перевірити до запуску.
- **Первинне ТЗ не передбачало комерційного маршруту до лікаря у версії 1.** Ми його додали
  на пряме рішення замовника; це посилює вимоги до розкриття умов партнерства й до окремої
  згоди на передачу даних.
- **Дві згоди.** Згода на обробку даних про здоров'я і згода на передачу конкретному
  отримувачу — це різні документи, і другий ще треба написати під конкретного партнера.

## Прев'ю одним файлом

```bash
python3 tools/build_preview.py            # -> site/dormeza-preview.html
python3 tools/build_preview.py /шлях.html
```

Збирає всі 12 сторінок в один самодостатній HTML: стилі, шрифти й зображення
інлайняться, переходи між сторінками стають клієнтськими. Зручно надіслати
юристу чи клінічному рецензенту — відкривається подвійним кліком, без сервера.
Це лише прев'ю: продакшн — окремі файли.
