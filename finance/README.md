# Steffany · Фінанси

Оперативний облік грошей салону «Майстерня краси Steffany» (Київська 77): рахунки ФОП, каса салону,
сейф, «Робочі гроші». Заміна Nomi.

* **Огляд** — загальна сума й баланс кожного рахунку, оновлення раз на годину (08:00–21:00 Київ).
* **Операції** — усі транзакції з 01.09.2026, фільтри, пошук, CSV. Редагування/видалення з повною історією змін (видалене можна відновити).
* **Категорії й правила** — авторозподіл за описом; нові категорії створюються автоматично для компаній-контрагентів; правила створюються вручну або прямо з операції.
* **Звіти** — день / тиждень / місяць / довільний період, по категоріях, рахунках, днях; експорт Excel.
* **Ролі** — власник, бухгалтер, адміністратор (додавати/редагувати/видаляти операції, бачити всі рахунки). Рахунки, токени банку й користувачів змінює лише власник.

## Звідки дані
| Рахунок | Джерело |
|---|---|
| ФОП 1, ФОП 2 | Приватбанк, API «Автоклієнт» (тільки читання): виписка та залишок |
| Каса салон | Alteg («Основна каса» філії 751396): оплати плюсом; зняття з каси — витрата, а якщо в коментарі «інкасація» — переказ у «Сейф» |
| Сейф, Робочі гроші | вручну (інкасація — переказ «Каса салон → Сейф», поповнення картки — переказ «Каса салон → Робочі гроші») |

Безготівка з Alteg не імпортується (вона приходить з банку), дзеркальні записи Alteg «Сейф» ігноруються.

## Розгортання (Fly.io, приблизно $2–4/міс)
```
fly launch --no-deploy --copy-config
fly volumes create data --size 1 --region waw
fly secrets set SECRET_KEY=$(openssl rand -hex 32) \
  OWNER_EMAIL=... OWNER_PASSWORD=... API_TOKEN=$(openssl rand -hex 24) \
  ALTEG_PARTNER_KEY=... ALTEG_LOGIN=... ALTEG_PASSWORD=...
fly deploy
```
Резервна копія: `fly volumes snapshots`. Після входу власника: «Рахунки» → ФОП → IBAN і токен Автоклієнта → «Перевірити з'єднання».

## Змінні середовища
`SECRET_KEY` (обов'язково; шифрує токени банку), `OWNER_EMAIL`/`OWNER_PASSWORD` (створюють власника при першому запуску),
`API_TOKEN` (читання звітів через `/api/*`, заголовок `X-API-Token`), `ALTEG_*`, `HISTORY_START`, `DB_PATH`.

## JSON API
`GET /api/balances`, `GET /api/report?date_from=2026-10-01&date_to=2026-10-19[&account=ID][&details=1]`.

## Правило: коментарі до візитів в Alteg читаються завжди

Адміністратори пояснюють нестандартну оплату візиту в полі «Коментар до візиту» в Alteg. Програма підтягує коментарі
за поточний і минулий місяць при кожному оновленні з Alteg, а також при кожному нарахуванні ЗП, і враховує їх у звітах
(«Нарахування ЗП»: каса майстра, перевірки D6–D8, Excel). Усі коментарі читаються як звичайний текст, `#` не потрібен. Розпізнаються слова:

- `#сертифікат 880`, `#бали 880`, `#бонуси 880` — оплата не грошима, сума додається до каси майстра цього візиту;
- `#переробка Прізвище 900` (або «переробка після Прізвище, 900грн») — сума переходить від майстра, чию роботу переробляли, до того, хто переробляв;
- `#подарунок` — безкоштовно навмисно, нічого не додається;
- «бартер» / «блогер» — візит безкоштовний для блогера, але майстру % нараховується з повної суми;
- «відмовився оплачувати» / «відмова від оплати» — клієнт не заплатив, % майстру не нараховується;
- `Рикова25` — клієнтка має знижку 25%, а майстру ЗП нараховується з повної суми (відсоток береться з числа в мітці).

Якщо суму не вказано, береться різниця між прайсом і оплатою візиту. Візит, оплачений менш ніж на 60% від прайсу
без жодної мітки, потрапляє в «Контроль» і в перевірку D8 звіту. Мітка, яку не вдалося зрозуміти (наприклад, невідомий
майстер у переробці), теж потрапляє в «Контроль». Код: `app/payrun.py` (`parse_mark`, `visit_effects`, `sync_visits`).
