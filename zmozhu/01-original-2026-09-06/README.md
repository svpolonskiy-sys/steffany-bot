# ZMOZHU — лендинг

Односторінковий лендинг 30-денної програми супроводу зниження ваги для жінок
(працює через Telegram-бот). Мета сторінки — одна дія: перехід у Telegram-бот
для реєстрації та оплати мотиваційного внеску.

---

## 1. Стек

- **Next.js 14** (App Router) + **TypeScript**
- **Tailwind CSS** (кастомні кольорові токени)
- **Framer Motion** (стримані анімації появи, з підтримкою `prefers-reduced-motion`)
- Деплой розрахований на **Vercel**

Node.js: рекомендовано **18+** (розроблялося на Node 24).

---

## 2. Швидкий старт (локально)

```bash
# 1. Встановити залежності
npm install

# 2. Створити файл оточення з прикладу
cp .env.example .env.local
# і за потреби змінити значення (див. розділ 3)

# 3. Запустити дев-сервер
npm run dev
# → http://localhost:3000

# Продакшн-збірка (перевірка перед деплоєм)
npm run build
npm run start
```

## 7. Підводні камені — прочитати до першої правки

Три речі, на яких легко втратити годину. Усі перевірені на практиці.

### 7.1. Замінили картинку — а на сайті стара

Next.js кешує оброблені зображення в `.next/cache/images`, і ключ кешу —
це URL, а не вміст файлу. Якщо покласти новий файл під тією самою назвою,
сайт продовжить показувати стару картинку. Перезавантаження сторінки
не допомагає.

```bash
rm -rf .next/cache/images
```

Далі перезавантажити сторінку. Дев-сервер зупиняти не треба.

Щоб не наступати на це щоразу, є два підходи: чистити кеш після кожної
заміни, або давати новим файлам нові імена (`tanya-hero-v2.jpg`) і
міняти `src` у розмітці. Другий варіант надійніший, якщо картинку
оновлюють часто.

### 7.2. Не запускати `npm run build`, поки працює `npm run dev`

Збірка перезаписує теку `.next`, з якої в цей момент віддає файли
дев-сервер. Результат: сторінка відкривається, але всі стилі й скрипти
віддають 404 — сайт виглядає так, ніби «поплив».

Це не поломка коду. Порядок дій, якщо таке сталося:

```bash
pkill -f "next dev"
rm -rf .next
npm run dev
```

Правильний порядок: спершу зупинити дев-сервер, потім збирати.

### 7.3. Анімації не запускаються у фоновій вкладці

Анімації працюють на `requestAnimationFrame`, а браузер зупиняє його
в невидимих вкладках і схованих панелях. Якщо перевіряєте анімації
через вбудований прев'ю-браузер IDE — вони можуть не відпрацювати.
Це не баг, перевіряти треба у видимому вікні.

## 9. Анімації

Реалізовані на Framer Motion, який уже стояв у проєкті. Усі поважають
системне «зменшити рух» (`prefers-reduced-motion`) — тоді сторінка
статична.

| Компонент | Що робить |
|---|---|
| `MiraChat.tsx` | Повідомлення бота з'являються по черзі, у шапці «друкує…» |
| `DepositFlow.tsx` | Механіка \$50 проявляється частинами |
| `DayCycle.tsx` | Крапки мікросхеми дня пульсують по колу |
| `CountPercent.tsx` | Відлік цифри від 0 до −4% |
| `Reveal.tsx` | Загальна поява блоків при скролі |

Тексти всіх анімованих блоків присутні у серверному HTML — на SEO
анімації не впливають.

### Відоме обмеження доступності (не виправлено свідомо)

Акцентний текст кольору `#D98368` на кремовому тлі дає контраст **2.66:1**.
Для великих заголовків норма 3:1, для дрібного тексту 4.5:1 — тобто не
проходить ні там, ні там. Виправлення означало б притемнити терракоту
по всьому сайту й змінити його вигляд, тому рішення винесено на замовника.
Стосується: надзаголовків (`30 ДНІВ · ЩОДЕННА ПІДТРИМКА · −4% ВАГИ`),
кольорових частин заголовків, підписів у картках.

### Точні правила програми (узгоджені із замовником)

Внесок повертається за одночасного виконання трьох умов:
1. зниження ваги мінімум на 4% від стартової, без різких стрибків; результат
   рахується як середнє за 3 останні дні зважувань;
2. щонайменше 27 ранкових і 27 вечірніх чекінів за 30 днів (допустимо
   пропустити до 3 і до 3);
3. щоденне зважування з фото та секретним словом (допустимо пропустити до 3).

Система відстежує динаміку ваги; за ознак зловживання діуретиками чи
проносними засобами участь може бути зупинена без повернення внеску. Повні
формулювання — в `app/oferta/page.tsx` та `app/refund/page.tsx`. На лендингу
ці правила подані спрощено — при зміні умов треба синхронізувати обидва місця.

## 12. Деплой на Vercel

1. Залити код у Git-репозиторій (GitHub/GitLab).
2. На [vercel.com](https://vercel.com) → **Add New → Project** → імпортувати репозиторій.
3. Framework Preset визначиться автоматично як **Next.js**.
4. Додати змінну оточення `NEXT_PUBLIC_TELEGRAM_BOT_URL`.
5. **Deploy.**
6. **Domains:** Project Settings → Domains → додати власний домен і
   прописати DNS-записи, які покаже Vercel.

Альтернатива (CLI):
```bash
npm i -g vercel
vercel            # прев'ю-деплой
vercel --prod     # продакшн
```
